# 家的菜单 · 网页版

两个人一起用的家庭菜单：各自上传菜品和做法，一起点菜，自动汇总备菜清单，还能生成一张"今日菜单"图片发到家庭群。

纯前端（HTML + CSS + 原生 JS），不需要服务器、不需要登录。打开网页就能用，数据先存在自己设备上；想两台手机互通，接一个免费 Supabase 项目即可（5 分钟）。

---

## 一、先在本机看看

双击 `index.html` 就能打开（Chrome / Edge / Safari 都行）。
本地直接打开时，图片和本地存储都正常，只是"两人同步"要等接入 Supabase 后才生效。

想在手机上看效果：把整个 `family-menu-web` 文件夹放到任意静态服务器，或按下面第二步上线。

---

## 二、上线（三分钟，免费）

### 方案 A：Netlify Drop（最简单，不用命令行）

1. 打开 <https://app.netlify.com/drop>
2. 把整个 `family-menu-web` 文件夹拖到页面中间
3. 等十几秒，得到一个 `https://xxxx.netlify.app` 的网址

这个网址在手机浏览器打开就能用，也可以"添加到主屏幕"当 App 用。
（不登录也能用，但链接可能一段时间后被回收；用 GitHub/邮箱登录一下就能永久保留。）

### 方案 B：GitHub Pages（有 GitHub 账号的话）

1. 新建一个仓库，把 `family-menu-web` 里的文件传上去
2. 仓库 Settings → Pages → Source 选 `main` 分支 / `root`
3. 一分钟后就得到 `https://你的用户名.github.io/仓库名/`

### 方案 C：自己已有的服务器 / 对象存储

把 `family-menu-web` 目录里的文件原样上传即可，不需要任何后端。
注意必须是 HTTPS，否则浏览器会限制部分能力（比如剪贴板、添加到主屏幕）。

## 三、两台手机同步（可选，免费，5 分钟）

不配置也能用，只是两台手机各记各的。想互通就接一个 Supabase（免费额度对家庭用绰绰有余）。

1. 打开 <https://supabase.com>，用 GitHub 或邮箱注册（免费）
2. New project，随便起个名字，Region 选 Singapore 或 Tokyo，等 1~2 分钟初始化
3. 左侧 **SQL Editor** → New query → 把项目里的 `supabase.sql` 全文粘进去 → Run
   看到 "Success. No rows returned" 就对了
4. 左侧 **Project Settings → API**，复制两个值：
   - **Project URL**（形如 `https://abcdefgh.supabase.co`）
   - **anon public** key（一长串 `eyJ...`）
5. 回到网页 → 底部「我的」→「云端同步」→「开启两人同步」→ 把两个值粘进去 → 保存并连接

状态变成「已连接」后，两个人的菜品和点菜会在 5 秒内自动同步。

### 两个人怎么连到一起

- 第一个人在「我的」页看到一串 **8 位家庭码**，比如 `VFES5JKB`
- 点「复制邀请链接」，把链接发给她/他；对方打开链接，自动加入同一个家
- 或者对方在自己手机上打开网页 → 我的 → 输入同一个家庭码 → 加入

> 家庭码只是把数据分组，没有密码。别把邀请链接发到公开场合。

## 四、日常怎么用

| 想干什么 | 怎么做 |
| --- | --- |
| 加一道新菜 | 菜单页右下角 **＋**，或右上角「＋ 加菜」 |
| 拍照 / 选图 | 编辑页顶部虚线框，图片会自动压缩到 720px，不占空间 |
| 拆配菜和佐料 | 编辑页下方「🧺 配菜」「🧂 佐料」，一行一个，写清用量 |
| 点菜 | 菜单卡片右下角的 **＋**，点几次就是几份 |
| 看今天吃什么 | 底部「餐桌」，可以加减份数、清空重来 |
| 买菜 | 餐桌页「🧺 备菜清单」，自动把几道菜的配菜合并去重，边买边勾 |
| 发家庭群 | 餐桌页「生成今日菜单」→ 生成图片 → 保存 / 分享 |
| 随机决定 | 首页「今晚吃什么」卡片，帮你从菜单里抽一道 |

点进一道菜，配菜和佐料前面有圆圈，做饭时打勾，退出会记住。

## 五、数据存在哪

- **本地模式**：全部存在浏览器的 IndexedDB/localStorage 里，换浏览器或清缓存就没了。
  「我的 → 数据」→ **导出菜谱** 可以存一份 JSON 到手机。
- **同步模式**：除了本地一份，还会写到你自己创建的 Supabase 数据库（Postgres）。
  数据只在你自己的项目里，不经过任何第三方。

图片以 base64 存在数据库的 text 字段里（已压缩到 720px 宽、约 0.7 质量，一张 60~120KB）。
家庭几十道菜的量级完全够用。

## 六、和小程序版的关系

同目录下的 `family-menu` 是微信小程序版，功能一样，已经上传到微信后台。
两者的数据**不互通**（存储位置不同），选一个长期用就行：

- 想在微信里直接用、给家人扫码 → 用小程序
- 想随时打开、不依赖微信、跨设备方便 → 用网页版，链接存到手机桌面

## 七、文件说明

```
family-menu-web/
├── index.html            页面骨架（只有一个 #app 容器）
├── style.css             全部样式（奶油底 + 暖橙，手机优先）
├── app.js                全部逻辑：路由、渲染、存储、同步、生成菜单图
├── config.js             同步配置（可留空，也可以手动填死）
├── supabase.sql       建表 + 权限，粘到 Supabase SQL Editor 执行
├── manifest.webmanifest  添加到主屏幕时的名字、图标、主题色
├── icon-180.png           iOS 主屏图标
├── icon-192.png           安卓主屏图标
└── icon-512.png           高清图标
```

没有任何构建步骤，也没有依赖。改完直接刷新页面即可。

## 八、常见问题

**Q：两个人都打开了网页，但我加的菜对方看不到？**
A：检查「我的」页顶部的状态标签，应该是「已同步」。如果显示「仅本机使用」，说明还没接 Supabase，或者家庭码不一样（对比一下 8 位码是否一致）。

**Q：换手机了，数据怎么办？**
A：有同步的话，新手机打开同一个链接 + 同一个家庭码，5 秒内自动拉下来。
没有同步的话，先在旧手机「我的 → 数据 → 导出菜谱」拿到 JSON，再在新手机用「导入菜谱」。

**Q：能离线用吗？**
A：能打开已缓存的页面，但离线时不能同步，改的内容会在下次联网时补传。

**Q：会不会有人通过链接看到我家的菜单？**
A：别人只知道网址的话，看到的是他自己浏览器里的空白家（本地存储），不会看到你的。
如果对方有你的家庭码，就能看到——所以家庭码等同于密码，别外传。

**Q：能加语音、评论、购物车结算吗？**
A：可以在此基础上继续加，但会有额外的存储和接口需求。
