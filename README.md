# 家的菜单 · 网页版

两个人一起用的家庭菜单：各自上传菜品和做法，一起点菜，自动汇总备菜清单，还能生成一张"今日菜单"图片发到家庭群。

纯前端（HTML + CSS + 原生 JS），不需要服务器、不需要登录。打开网页就能用，后台用的是 Supabase 免费版，两台手机的数据 5 秒内自动同步。

## 五、数据存在哪

- **本地模式**：全部存在浏览器的 IndexedDB/localStorage 里，换浏览器或清缓存就没了。
  「我的 → 数据」→ **导出菜谱** 可以存一份 JSON 到手机。
- **同步模式**：除了本地一份，还会写到你自己创建的 Supabase 数据库（Postgres）。
  数据只在你自己的项目里，不经过任何第三方。

图片以 base64 存在数据库的 text 字段里（已压缩到 720px 宽、约 0.7 质量，一张 60~120KB）。
家庭几十道菜的量级完全够用。

### 关于 key 的公开性（重要）

Supabase 的 publishable key 设计上就是公开的（能放进网页的 key），它靠数据库的 RLS 规则控制权限。
本项目为了让家人**打开链接就自动连上**，支持把 key 写进 `config.js`：

```js
window.FAMILY_MENU_CONFIG = {
  supabaseUrl: 'https://xxxx.supabase.co',
  supabaseAnonKey: 'sb_publishable_...'
};
```

方便，但要知道代价：**拿到网址和 key 的人，理论上能通过 API 读到整张表**（也就是所有家庭的数据，不只是你的）。

- 介意的话：不要在 `config.js` 里写，改成每个人自己在页面里填（各自的 key 只存在自己浏览器里，别人拿不到）
- 或者：定期到 Supabase → Settings → API 里轮换 key，同时更新 `config.js`
- 对"就两个人用、网址不外传"的场景，风险很小，但不要把它当保险箱

## 七、常见问题

**Q：两个人都打开了网页，但我加的菜对方看不到？**
A：检查「我的」页顶部的状态标签，应该是「已同步」。如果显示「仅本机使用」，说明还没接 Supabase，或者家庭码不一样（对比一下 8 位码是否一致）。

**Q：换手机了，数据怎么办？**
A：有同步的话，新手机打开同一个链接 + 同一个家庭码，5 秒内自动拉下来。
没有同步的话，先在旧手机「我的 → 数据 → 导出菜谱」拿到 JSON，再在新手机用「导入菜谱」。

**Q：能离线用吗？**
A：能打开已缓存的页面，但离线时不能同步，改的内容会在下次联网时补传。

**Q：会不会有人通过链接看到我家的菜单？**
A：别人只知道网址的话，看到的是他自己浏览器里的空白家（本地存储），不会看到你的。
如果对方有你的家庭码，就能看到——所以家庭码等同于密码，别外传。

**Q：能加语音、评论、购物车结算吗？**
A：可以在此基础上继续加，但会有额外的存储和接口需求。
